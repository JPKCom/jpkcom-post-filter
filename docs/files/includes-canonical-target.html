canonical-target.php

Canonical targets – which original page a filter page may point at

A filter page with one term shows what the term archive shows; a combination is a view of the archive base. Since 1.7.0 their canonical points there - but only at a target that is itself indexable. A canonical to a noindex page tells a search engine to drop both.

Decisions only, no hooks. The canonical decision and its output live in includes/crawl-guard.php.

Rank Math and Yoast are read the way they decide their own robots (read in Rank Math 1.0.280 includes/frontend/paper/ and Yoast 28.2 src/builders/indexable-*-builder.php / src/presentations/), and only while the plugin is active: options of a deactivated SEO plugin stay in the database and say nothing about the page any more.

Whether an active SEO plugin gives a target a canonical of its own elsewhere

jpkcom_postfilter_seo_canonical_moved(string $url, WP_Term|null $term, int $page_id) : bool

An editor can point a term archive or the posts page at another URL (Rank Math rank_math_canonical_url, Yoast wpseo_canonical / _yoast_wpseo_canonical). A canonical to such a target would be a chain; the target is then unusable and the filter page keeps its own canonical.

jpkcom_postfilter_term_archive_lists_post_type()

canonical-target.php : 203

Whether the archive of a taxonomy's terms lists a post type

jpkcom_postfilter_term_archive_lists_post_type(string $taxonomy, string $post_type) : bool

Mirrors WP_Query::get_posts() for an archive query without a post type (wp-includes/class-wp-query.php, 7.1.3 l. 2310-2333): only a custom taxonomy sets is_tax, and only then does core search every post type with exclude_from_search = false that has the taxonomy. Category and tag archives set is_category / is_tag instead and query post alone. A theme's pre_get_posts is invisible here; the filter jpkcom_postfilter_canonical_archive_indexable covers that.

Parameters
$taxonomy : string

Taxonomy.

$post_type : string

Post type of the filter page.
