server-rules-admin.php

Server Rules – the admin page

Spec 6. A sub-page of "Post Filter" that brings the generator (includes/server-rules.php, includes/server-rules-render.php), the .htaccess management (includes/htaccess-manager.php, includes/htaccess-sync.php) and the status check (includes/server-rules-check.php) together. It decides nothing about the rules itself: every snippet, limit, probe and status comes from those files, so what the page shows is what the tests there prove.

  • Head: the detected web server, warnings, the effective inputs, the form for the rate-limit inputs (own option jpkcom_postfilter_server_rules) and the status box with "Check now".
  • One tab per server (nginx, Apache server configuration, Apache .htaccess, Caddy, Ferron 3, Ferron 2.8, OpenLiteSpeed), the detected one preselected, all of them available. Each with its snippets and copy buttons, the order rule, curl checks and the page-cache hint; the .htaccess tab also with the box that sets the managed block up or removes it.

The decisions are pure helpers (tests/test-server-rules-admin.php); the render functions only print what they return. Every action checks manage_options and a nonce and redirects back with a message KEY - the text comes from a fixed list, never from the URL.

The server family a SERVER_SOFTWARE value names

jpkcom_postfilter_server_rules_htaccess_action()

server-rules-admin.php : 454

"Set up" or "Remove" the managed .htaccess block

jpkcom_postfilter_server_rules_htaccess_action(string $do[, array<string, mixed>|null $inputs = null ]) : string

install: only when jpkcom_postfilter_htaccess_available() allows it; writes the block for the current inputs, then stores the file's path in the option jpkcom_postfilter_htaccess_managed (not autoloaded). With no reject part the option is set anyway and the block follows once there is one.

remove: whenever the file can be written, whatever available() says - removing only loosens, and after a server move it is the only way to get rid of a leftover block. The option goes only when no managed block (and no damaged marker) remains, so a block that could not be removed stays guarded.

The caller checks capability and nonce.

Parameters
$do : string

install|remove.

$inputs : array<string, mixed>|null = null

Rule inputs, null for the current ones.

Tags
since
1.6.0
Return values
string —

Message key for jpkcom_postfilter_server_rules_message(), '' for an unknown action.
